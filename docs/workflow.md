# 部署与验证流程

给人和 Agent 的长说明。硬性禁令见根目录 [`AGENTS.md`](AGENTS.md)，逐步入口见 [`SKILL.md`](SKILL.md)。

`install.sh` 把下面的步骤做成了三段：`--check`（只读探测）、`--dry-run`（强制预览）、`--apply`（确认后写入，不重启）。本页写的是每一步该遵守的顺序；不用安装器、手动部署时也按这个来。

## 环境探测（只读）

在用户指定的目标机上收集，能报什么报什么，缺的标「未确认」。不要为了探测而重启服务。

| 项 | 怎么看（按实机调整） | 说明 |
|---|---|---|
| 是否为 OpenWrt / ImmortalWrt | `/etc/openwrt_release`、`/etc/os-release` | 历史证据来自 ImmortalWrt SNAPSHOT，不代表只支持那一版 |
| 架构与内核 | `uname -m`、`uname -r` | 历史环境为 aarch64、Linux 6.6.69 |
| 内存与 swap | `/proc/meminfo` | 历史机器 MemTotal 485 MB、无 swap；可用内存偏低时不要做全量 `clash -t` |
| OpenClash 是否安装 | `/etc/init.d/openclash`、`/etc/openclash/` | 版本号在历史资料里未能确认，不要编。能从 `opkg` 或 LuCI 读到就记录来源 |
| Mihomo / 内核二进制 | `/etc/openclash/core/clash_meta` 是否存在 | 历史为 `alpha-g86257fc`，用户机器可能不同 |
| Ruby | `ruby -v` | 历史注入依赖路由器 Ruby；没有 Ruby 时不得假装钩子仍完整可用 |
| 生效配置路径 | 从实机上的 OpenClash 读取 | 不得使用仓库占位符 `__PRIVATE_CONFIG__` 去连机器 |
| 带外管理 | 改网络失败后是否还能登入 | 没有带外方案要先告诉用户 |

也可运行仓库根目录的 `./install.sh --check`。把探测结果写成：已确认 / 未确认 / 风险。然后停下来给用户看。

## 用户必须提供的

使用 `config.example.yaml` 的结构，复制为本地 `config.yaml`（不要提交填好的文件）。`claude.node_match`（Ruby 正则，必须恰好命中一个订阅节点）和 `claude.alias`（改名后成为 `Claude专用` 组首位的显示名）会被 `scripts/claude_inject.sh` 读取，缺一不可。订阅地址只能来自用户放到路由器上的凭据文件。

至少要有：这两项节点配置、目标主机与登录方式、凭据文件路径（助手不读内容）、失败时的行为、维护窗口、是否允许重启、回滚联系方式。

`config.example.yaml` 里的 `美国01` / `Claude-Node` 只是中性示例，禁止原样当成用户的节点。`Claude专用` 是项目的功能组名，保持不变。

## 强制预览

任何写入之前，必须给出并得到同意：

1. 将要改哪些文件（完整路径）
2. 将要安装或替换哪些脚本
3. 会不会重启或重载服务
4. 预期的校验命令和成功标准
5. 失败时的回滚命令
6. dry-run 产物只写临时目录，不覆盖生效文件（`./install.sh --dry-run` 输出的就是这六项）

没有预览结果，就不要申请进入维护窗口。

## 写入步骤（一步一校验；`--apply` 自动做 3、4、6 和部分 8）

1. 只读探测 → 环境报告。
2. 确认 `config.yaml` 中 `claude.node_match` 与 `claude.alias` 已填写且能在订阅里恰好命中一个节点；不回显秘密。
3. 备份钩子、当前配置、将被替换的自定义脚本 → 记录哈希，确认备份可读。
4. 安装用户确认过的文件，权限收紧。
5. 凭据由用户放到约定路径；助手只检查存在与权限。
6. 临时目录构建与校验；内存足够时才做全量内核校验。
7. 仅在用户明确同意的维护窗口重启。
8. 启动后验证：钩子是否离线命中缓存、规则是否命中指定组、非目标流量是否仍走原策略。
9. 交付报告，区分已执行 / 已验证 / 未验证。

## 回滚

- 默认只检查，不修改。
- 恢复钩子到安装前备份，并核对哈希。
- 这一步失败就停止，不要继续删除凭据或缓存。
- 不自动重启；需要重启时单独问用户。
- 回滚后验证：自定义注入是否已撤、非目标策略是否恢复、服务是否仍可用。
- 具体命令必须来自这次部署前备份，而不是仓库里写死的路径。用 `--apply` 装过时，`claude_rollback.sh` 会从 `.claude_backup/install.manifest` 读原始钩子的 md5 / sha256 和运行配置路径；默认只检查，加 `--apply` 才执行。安装前的完整备份在 `.claude_backup/install_<时间戳>/`，可用 `sha256sum -c SHA256SUMS` 核对。

## 必须再问用户的节点

第一次写入；安装或替换钩子 / 注入 / 更新 / 回滚脚本；重启或重载服务；创建、读取、复制、删除凭据；扩大规则范围；预览与实机环境不符；验证失败后是回滚、停机保留现场，还是改计划。一次问清一件事，附上影响和回滚方式。
